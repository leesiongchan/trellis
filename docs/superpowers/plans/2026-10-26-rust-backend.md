# Rust Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Node production server with one Rust service while preserving Branch's browser data, access capabilities, research contracts, and demo behavior.

**Architecture:** Keep the Svelte UI and IndexedDB storage. Prerender the app shell, package its assets beside a Rust executable, and use Axum for same-origin access/research/operational routes. A bounded coordinator owns cancellable research tasks; provider HTTP adapters and grounding checks remain independently testable.

**Tech Stack:** Rust 2024, pinned Rust 1.98.0, Axum 0.8.9, Tokio 1.54.1, Tokio-util 0.7.20, Tower HTTP 0.7.1, Reqwest 0.13.5 with Rustls, Serde, tracing, prometheus-client 0.25.1, Hyper 1.12.0; existing SvelteKit 3.1.0/Svelte 5.57.2, adapter-static 4.0.0, Node 26.5.0, pnpm 11.21.0, Vitest, Playwright.

## Global Constraints

- One Cargo package under `backend/`; one production process; loopback listeners and the existing private Tailscale origin.
- Rust 2024; committed `Cargo.lock`; pinned toolchain; no application unsafe code, production `unwrap`/`expect`, or secret-bearing Debug output.
- Request body: 65,536 UTF-8 bytes. Incoming body read: 10 seconds.
- Distinct active research jobs: 2. New jobs: 10 per rolling 60 seconds. Research waiters: 32 total requests, including original requests.
- Search stage: 20 seconds within the job deadline. Whole research job: 120 seconds from admission.
- Upstream connection establishment: 5 seconds within the remaining stage/job deadline. Each upstream response body: 2 MiB.
- HTTP connections: 128 concurrent connections. Stop accepting during shutdown; drain for 125 seconds and exit within 130 seconds; second termination signal forces exit.
- At most five sources and 12,000 UTF-16 units of text per source; preserve every semantic bound in `src/lib/knowledge/schemas.ts`.
- Seven-day `branch_access` cookie, existing HMAC format, exact Origin/Host checks, existing API shapes/error codes, IndexedDB `branch-knowledge-v1` version 1, and exploration schema version 1 remain compatible.
- No new model/provider, automatic retries, public access, database, cross-device synchronization, deployment, or paid provider calls. Preserve `OPENAI_MODEL` and its existing default `gpt-5.6-terra`; availability remains unverified.
- Preserve port 60090 and active forwarding. Tests use dedicated loopback ports and never stop the user's running app.
- Keep existing pnpm lifecycle-script policy (`allowBuilds: {}`); inspect any required exception before changing it. Use comma for missing CLI tools on this Nix system.
- Every task uses a red/green cycle for the listed behavior and commits only its files after checks pass. Later tasks consume the Interfaces blocks below. Do not introduce temporary production bypasses to simplify tests.

## Review Focus

- Astral Unicode, ECMAScript whitespace, and missing nullable properties must produce the same normalized requests/acceptance as Zod; Task 1 pins this.
- A stale cancelled job must never delete or publish into a replacement job for the same request; Task 5 pins this race.
- A requester that disconnects during research must release its waiter without cancelling another requester's shared work; Tasks 5 and 8 pin this over actual sockets.
- A release launched from a different working directory, or with an escaped asset symlink, must find only its packaged assets and never expose local files; Task 7 pins this.
- An unchanged browser origin after upgrade must retain pre-migration IndexedDB state and accept the old signed cookie, including on HTTPS; Task 9 pins this without changing the user's deployment.
